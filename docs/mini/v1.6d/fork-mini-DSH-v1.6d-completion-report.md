## Versions and artifacts

- Schema version: `PROJECT_LEDGER_SCHEMA_VERSION = 9` — nine frozen adjacent steps (0→1→…→9, one `BEGIN IMMEDIATE` transaction each); v1.6d added four of them (5→6 assignments, 6→7 handoffs, 7→8 reservations, 8→9 conflicts). The committed v1 fixtures stayed stamped 1 and remain the standing upgrade probes: every committed generation opens through all shipped steps on a copy, rows intact.
- Event format version: `PROJECT_EVENT_FORMAT_VERSION = 9`; the vocabulary is 31 required event types — the 24 types through v1.6b plus seven v1.6d additions (`work/assigned`, `handoff/recorded`, `scope/reserved`, `scope/released`, `scope/expired`, `conflict/recorded`, `conflict/resolved`), each with payload validation and a replay applier. The decoder rejects only rows stamped newer than the build (`this build reads up to format 9`), so a timeline mixing stamps 1–9 decodes clean.
- Tables (27): the 23 tables through v1.6b plus `work_assignments`, `handoffs`, `scope_reservations`, `collaboration_conflicts`.
- Indexes added with the new tables: the partial unique index `uq_one_live_primary_per_work(work_item_id) WHERE status = 'ACTIVE' AND assignment_kind = 'PRIMARY'`, `idx_work_assignments_item`, `idx_work_assignments_actor`; `idx_handoffs_item`; the blueprint's `idx_scope_active` as-is, the partial unique index `uq_one_active_reservation_per_scope(project_id, scope_kind, scope_value) WHERE status = 'ACTIVE'`, and `idx_scope_reservation_expiry`; `idx_conflicts_item_a`.
- Adaptations, recorded per domain in the module docs and Agent Notes: the v1.6b actor rows turned the blueprint's actor strings into foreign keys, so every v1.6d table references `work_items`, `actors`, and (where nullable) `roles` directly; `project_id` derives through the work item in the assignment, handoff, and conflict tables, while the reservation table keeps its own column because the scope's uniqueness predicate leads with it; inline text replaces `*_content_id` indirection (handoff `summary`, conflict `description`); `repo_snapshot_id` is dropped (no referent); kind vocabularies close to what a consumer distinguishes — all six `assignment_kind` values at once (extending a CHECK costs a migration step), `handoff_kind` to `DELEGATE`/`RETURN`, `scope_kind` to `PATH`, `conflict_kind` to `SCOPE_OVERLAP`; and the blueprint reservation `mode` column is dropped — every reservation ships exclusive, and a column with one legal value is noise.
- Two invariants are database facts, not only seam checks: one live `PRIMARY` assignment per work item, and one active reservation per project scope — each a partial unique index, a seam refusal, and a fold check at once.
- Stage granularity deviates from the proposal's wording on purpose: stage A shipped as two migrations (assignments, then handoffs) rather than one combined step, so no table lands before its events; the deviation is recorded in the plan yaml and the Agent Note.
- WorkPacket format untouched (`WORK_PACKET_FORMAT_VERSION = 1`): the v1.6d domains add library seams and read-only views, no packet surface.

- **Handoffs (schema v7, format 7)** — §28 append-only pass-of-work records; exactly one recipient, an actor or a role, enforced by a CHECK, the seam, and the decoder at once; `handoff_kind` closed to `DELEGATE`/`RETURN`; no liveness scan — records are appended, never moved. Read-only `/project handoffs`.
- **Claim visibility (no schema change)** — the read side of per-actor coordination: a `viewerIdentity` on the todo request drops entries another identity holds a live claim on, `project_work_next` resolves the calling agent's identity at its own input, and a session-less listing stays the owner-style full queue. - **Scope reservations (schema v8, format 8)** — §21, one actor's exclusive claim on a project scope while working an item. The lifecycle mirrors the work leases completely: `reserveScope` expires a stale `ACTIVE` holder in-transaction (a dead row would block the partial unique index), `releaseScopeReservation` frees the scope and refuses a second release, `reapExpiredScopeReservations` moves the lapsed batch, and every row movement carries its required event. `expiresAtMs` is caller-named and must be in the future; no default TTL exists. Ids `sr:<projectId>:<eventSequence>`. First rows: `sr:mini-dsh:194` (the lane reserves `packages/experimental/project-ledger`) and `sr:mini-dsh:195` (`agent:second` reserves `packages/experimental/mini-profile`), both ACTIVE; a third reservation of an already-held scope is refused naming the holder. Read-only `/project reservations`.
- **Collaboration conflicts (schema v9, format 9)** — §29, records of two work items whose scopes still collided, raised by an actor. `conflict_kind` closes to `SCOPE_OVERLAP` — the containment overlap the equal-value reservation check cannot judge. ## What v1.6d deliberately leaves unwritten

A reservation lives exactly as long as its caller said — `expiresAtMs` has no default TTL, and expiry moves rows only through the writers that emit events.
