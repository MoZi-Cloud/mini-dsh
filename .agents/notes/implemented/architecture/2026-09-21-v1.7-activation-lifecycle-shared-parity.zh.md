# Agent Note：v1.7 激活生命周期与共享回放 parity

Status: implemented

[English](2026-09-21-v1.7-activation-lifecycle-shared-parity.md) | 中文

## 问题

评审 v1.1 的 F-02：激活没有权威写入者。required 事件 `plan/version-activated` 没有载荷解码器，落入 fold 的 default 分支；`ReplayedPlanVersion` 不携带任何生命周期事实；两个 parity sweep 都看不见对 `plan_versions.status`、生命周期时间戳、`plans.current_version_id` 的直接篡改。v1.6a BOOT 验收披露过这一推迟（"账本只存命令"——激活留给后续工作包），但至今每个 ACTIVE 版本都是 owner 的裸 UPDATE，时间线本身回答不了哪个版本是被合法激活的。相邻问题：doctor 按实体族重新实现了一套投影 parity（版本不在其中），而 `readProjectReplay` 拥有同样的比较——正是这种重复组织让一个 required 事件可以只登记类型而不带 decoder 和 fold。

## 决策

- **`activatePlanVersion` 是激活写入者（v1.6a §8）**：单个 `BEGIN IMMEDIATE` 要求版本处于 `DRAFT`、有对应的 `plan_imports` 行、该计划没有其他 `ACTIVE` 版本，然后写入 `status`、`activated_at_ms` 与 `plans.current_version_id` 指针，并追加严格的 `plan/version-activated` 事件（`planId`、`planVersionId`、`activatedAtMs`）。导入保持不激活；未经支持导入器进入的版本无法激活。
- **fold 拥有版本生命周期**：`plan/version-activated` 解码并折叠（status `ACTIVE`、戳记、指针）；`plan/version-superseded` 折叠其生命周期列，且仅当指针指向被退役版本时才重定位计划指针，与写入者逐列镜像。fold 不要求 supersede 之前必须有激活——迁移由写入者把关，而持久时间线里有六条在激活事件存在之前记录的 supersede。对未知版本、重放状态非 `DRAFT` 版本的激活，以及 plan 错配的激活，一律失败关闭。事件格式 9 → 10；schema 停在 9（`activated_at_ms` 与 `superseded_at_ms` 自 v1 就存在，无需迁移，评审的条件式迁移标准以"不迁移"满足）。
- **补录边界**：追加式时间线把任何追记的激活事件放在已记录的 supersede 之后，已接替版本永远无法获得一条看似合法的激活。即将进行的持久账本补录恰好覆盖三个现役版本；六条历史 supersede 按其事件记录的形状折叠。
- **投影 parity 唯一拥有者**：`readProjectReplay` 新增版本生命周期漂移（status、两个时间戳）与 `currentPlanVersions` 指针的双向比较；doctor 手写的按族 sweep 删除。doctor 把回放漂移转为 issue，只保留租约过期这项回放无法表达的运行健康检查。归一现在落地，因为把生命周期比较再写第二遍只会加深评审点名的重复。
- **接替加激活保持两操作**：无 ACTIVE 的中间态对调用者成文；原子性保证附着在每个操作上，没有消费者需要之前不交付复合 switch 写入者。

## 验证

- 三个包共 381 个测试覆盖新接缝：激活happy路径（行、戳记、指针、事件载荷、fold、指针 parity）、四种激活拒绝、激活折叠失败（未知版本、外计划、畸形字段、非 DRAFT 状态）、supersede 折叠出指针指向后继与指针置空两种形状、审计中的生命周期篡改发现（status、两个时间戳、指针）。
- 格式覆盖：比构建更新的行以 `this build reads up to format 10` 拒绝；此前经裸 SQL 激活的全部 fixture（六个 spec 文件、mini-profile 的 seeding 助手）改为经写入者建立 `ACTIVE`，parity 由构造保证。
- doctor 以 `projection-drift` 码上报转换后的漂移发现，干净账本保持安静；漂移消息措辞经 `readProjectReplay` spec 钉住的同一批收集器钉住。
- 门禁：包级 typecheck 绿；触及的包 oxlint 干净；编辑过的双语对重录 pairing。

## 被否决的备选

- **原子 switch 操作（一个事务内 supersede + activate）**——暂不采纳：没有消费者需要复合操作，单 owner 流程下无 ACTIVE 间隔无害，每个迁移一个写入者让 fold 保持简单。有消费者时再议。
- **只对戳记 format 10+ 的行折叠激活**——否决：按行戳的 fold 策略仍会把六个历史版本重放为 `DRAFT` 并对物化的 `SUPERSEDED` 报漂移；诚实的模型是 fold 重建事件所记录的一切。
- **doctor 保留自己的版本比较与回放并存**——否决：第二比较拥有者正是让 `plan/version-activated` 无 decoder、无 fold 也能登记的那种组织；doctor 只保留回放表达不了的部分。
- **为六个已接替版本补录激活事件**——否决：追加式时间线里这些事件会落在其 supersede 之后，fold 会正确拒绝该序列；它们的接替状态从已记录事件完全可以重建。

## 后果

- 词表文档不再把 `plan/version-superseded` 列为 validation-only；没有 decoder 和 fold case 的 required 事件类型现在是重放失败，原先把激活事件当"无投影效果"样本的测试被行为钉住取代。
- 阶段 A 其余条目解锁：持久账本补录（三个现役版本）与 benchmark worker 迁出直接生命周期 SQL，然后是 F-01 的受信 verifier consumer 对接同一评价接缝。
- 对任何版本生命周期列或计划指针的直接篡改，现在会以具名漂移发现出现在 `readProjectReplay` 与 doctor 中（A-08），写入者产出的每个 ACTIVE 版本都可追溯到其 required 事件（A-06、A-07）。
