# Agent Note: The v1.6d Per-Actor Claim Visibility

Status: implemented

English | [中文](2026-09-20-v1.6d-claim-visibility.zh.md)

## Problem

Stage A's closing item is the scheduling-projection change the v1.6d scope proposal promised: the v1.6a todo views shipped with a single-agent reality — one agent claims everything — so `project_work_next` listed every non-terminal item to every caller, another holder's live lease labeled but still in the queue. With the assignment and handoff domains shipped and a second AGENT actor about to register, that queue would show another agent's in-flight claims as the second agent's own work. The change must add no authority: readiness stays computed, and the ledger is at schema 7 with format 7 over a 180-event timeline, so a schema or format bump for a display filter would be misplaced weight.

## Decision

- **The view request gains a viewer identity, nothing else changes**: `viewerIdentity` on `WorkTodoRequest`, carried through the resolved spec and echoed on the view like `executorKinds`. With a viewer named, an entry another identity holds a live claim on drops out; unclaimed entries and the viewer's own stay listed. Without one, the view is the full queue — the same view the human `/project todo --agent` command reads.
- **The filter lives in the read, not in readiness**: no new blocker kind and no `computeWorkReadiness` change. A hidden entry's lease blocker was never the second agent's to read; the unfiltered view keeps surfacing holders exactly as before.
- **`project_work_next` resolves the viewer at its boundary**: a session that names an agent filters by `agent:<id>` (the same identity claims and evaluations record); a session-less execution has no identity to filter by and lists the full queue, explicitly resolved at the consumer rather than defaulted inside the view. An empty viewer identity fails loud (`empty-viewer-identity`) — a caller mistake, not a request for the unfiltered view.
- **The evidence run ends the pass at the actor who completes the item**: the second agent `agent:second` registers (event 169), the lane takes `PRIMARY` as `executor` on the closing item (`wa:mini-dsh:170`), the second agent claims (lease 171) — and the filtered views split exactly as designed: the lane's view hides the item, the second agent's view shows it held, the unfiltered view shows it labeled — then records the pass `ho:mini-dsh:172` (`DELEGATE` to the lane) and releases. The lane's run then claims, verifies, and completes the item `DONE`.

## Verification

- 345 tests across `project-ledger`, `project-ledger-sqlite`, and `mini-profile` at per-file 100% coverage: the resolve rejections, one test covering own-held/other-held/unclaimed under a viewer with the echo pinned, and a tool-level two-agent test where the other agent's `project_work_next` answers an empty queue while the holder still sees its lease; the session-less fallback is the pre-existing no-agent listing test, unchanged.
- Gates: oxlint 0/0, duplication at the standing two-clone baseline, cordis catalog clean.
- Lanes: the evidence run's snapshots (hide/show/label) came from the persistent ledger through the shipped seams; the lane run stored verifier exit 0 and `PA-CLAIM-VISIBILITY-001` `DONE` with doctor 0 issues and replay audit 0 drift; the idempotent rerun passed with zero tool calls; the 4K slice stayed green (max 2,444/4,096).

## Alternatives considered

- **A viewer-aware readiness blocker** — rejected: it would thread a viewer parameter through a claimability concept to serve a display filter, and the view is a read with no authority.
- **Failing loud on `project_work_next` without an agent session** — rejected: the sibling claim and update tools need the identity because they write; a listing with no viewer is the owner-style queue the command surface already exposes, so the fallback is explicit and documented at the tool.
- **Annotating other-held entries instead of hiding them** — rejected: the proposal's wording is visibility, not labeling; the unfiltered view keeps labeling for humans.
- **Passing the item from the lane to the second agent** — rejected: a registry actor cannot run a verifier or report; the second agent claims first to prove the visibility split, then delegates to the lane who completes, so the recorded pass ends where the work ends.

## Consequences

- v1.6d stage A closes with all three items `DONE`: assignments, handoffs, and per-actor claim visibility, on a timeline folding 180 events across formats 1–7 with two registered AGENT actors and one recorded pass between them.
- Stage B (parallel collaboration: scope reservations and conflicts) inherits the two-agent cast; both agents now read the same queue without seeing each other's live claims.
- A session-less `project_work_next` keeps listing everything; a future consumer that needs per-actor filtering without a session passes `viewerIdentity` explicitly.
