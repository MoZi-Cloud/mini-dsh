# Agent Note：v1.6d 范围预留域

Status: implemented

[English](2026-09-20-v1.6d-scope-reservation-domain.md) | 中文

## 问题

v1.6d 协作范围的阶段 B 以范围预留开篇(蓝图 §21):一个 actor 在某工作项上对项目范围的认领，让第二个 agent 看到该范围已被占用——这是阶段 B 并行协作的切片，经 §33 门槛以决策 `dr:mini-dsh:v1.6d-stage-b` 进入。本域继承如今的七层结构：schema 为 7、含七个冻结步骤，故表以恰好一次追加的 7→8 步落地；事件格式为 7、26 个 required 事件，压在 195 事件的持久时间线上。蓝图表需要一如既往的适配，而一个生命周期问题塑造了整个域：预留过期而持有者永不释放时怎么办。

## 决策

- **Schema v8 作为一次追加迁移（7 → 8）**：一张 `scope_reservations` 表——`project_id` 保留（蓝图的 `idx_scope_active` 以它打头，且范围的唯一性按项目划定，不同于靠 item 派生 project 的指派与交接表），外键直接引用工作项与 actor 行，`scope_kind` 对蓝图的未赋值集合收口为 `PATH`——本账本 agent 协调的唯一范围，重叠按同值判定——`status` 收口为 `ACTIVE`/`RELEASED`/`EXPIRED`，三者皆有写入者。蓝图的 `mode` 列删除：每个预留都是独占的，只有一个合法值的列是噪音而非可配置性。
- **每项目范围至多一条活跃预留是数据库事实**：部分唯一索引 `uq_one_active_reservation_per_scope(project_id, scope_kind, scope_value) WHERE status = 'ACTIVE'`、接缝的 `duplicate-reservation` 拒绝、fold 的第二条活跃检查——三层齐备，即 one-live-PRIMARY 模式。蓝图的 `idx_scope_active` 原样落地，另加一条过期索引镜像租约 reaper 的扫描。
- **生命周期镜像工作租约，含过期**：`reserveScope` 在一次 `BEGIN IMMEDIATE` 内校验并插入，先把仍占着范围的陈旧行转 `EXPIRED`（领取路径的 reap：死掉的 `ACTIVE` 行会卡住索引）；`releaseScopeReservation` 归还范围并拒绝二次释放；`reapExpiredScopeReservations` 成批移动过期行。每次迁移都带自己的 required 事件——`scope/reserved`、`scope/released`、`scope/expired`——因为没有事件的行移动是重放无法重建的折叠。`expiresAtMs` 由调用方指名且必须在未来；没有可供躲藏的默认 TTL。
- **事件格式 8 在相邻读取契约下**：三个事件加入 required 词表（26 → 29）；id `sr:<projectId>:<eventSequence>` 由时间线派生，因为已释放或已过期的范围必须能再次预留。释放与过期的时间戳不进重放事实——fold 派生 `status`，物化行拥有时间戳，如决策域的决策文本。
- **`SCOPE_RESERVATION_KINDS` 由事件编解码器拥有**（工作指派的教训）：写接缝与解码器校验同一个封闭集合。
- **读取经 join 解析标签**：`readProjectScopeReservations` 按最新在先返回携带 item `stableKey` 与 actor `actorKey` 的预留；`/project reservations` 渲染每行的生命周期——`ACTIVE` 显示到期、`RELEASED` 显示释放时间、reaper 的行显示 `expired`——按 `releasedAtMs` 的存在性分支，而不是留一个不可达的回退。

## 考虑过的替代

- **像指派与交接表那样删除 `project_id`**——拒绝：范围的唯一性按项目划定，部分唯一索引需要该列；蓝图的 `idx_scope_active` 以它打头。
- **保留蓝图的 `mode` 列（`EXCLUSIVE`/`SHARED`）**——拒绝：共享没有消费者，单值 CHECK 是没有语义的 schema 重量；独占就是这张表的本义。第二个 mode 出现时该列随其 CHECK 回归。
- **纯时钟活跃性、无 `EXPIRED` 写入者**——拒绝：陈旧 `ACTIVE` 行会永远卡住索引（没有写入者清除它），且无事件的行移动会破坏折叠奇偶；租约域的带事件过期模式是已验证的答案。
- **把 `scope_kind` 收口为 file/directory/package 集合**——拒绝：没有消费者区分它们，重叠反正按同值判定；`PATH` 是诚实的最小集合，真实第二类出现时付出一次 CHECK 迁移即可扩展。
- **配置里的默认预留 TTL**——拒绝：租约配置存在是因为领取工具需要策略默认；预留是调用方知晓时限的库接缝写入。隐式 TTL 会是接缝内部的隐藏 `?? default`。

## 后果

- 阶段 B 完成三分之一：`SB-CONFLICT-RECORD-001`（schema 8→9、format 9、冲突指向决策域）尚余，而两个 agent 的首批预留——lane 占 `packages/experimental/project-ledger`、第二个 agent 占 `packages/experimental/mini-profile`，都落在冲突条目上——正是冲突记录将要演练的分区。
- 持久账本就地折叠八种戳记的时间线（195 事件中 97+19+2+14+15+13+22+13）；v1.6d 计划版本 1 连同其三个 DONE 条目冻结，版本 2 激活阶段 B。
- 以预留协调的 agent 现在有了可指向的账本事实；当两个 agent 仍触碰同一范围时，冲突域记录漏网之鱼。
