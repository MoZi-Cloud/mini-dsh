# Agent Note：v1.6d 按 actor 的领取可见性

Status: implemented

[English](2026-09-20-v1.6d-claim-visibility.md) | 中文

## 问题

阶段 A 的收尾项是 v1.6d 范围提案承诺的调度投影变更：v1.6a 的 todo 视图带着单 agent 现实发布——一个 agent 领取一切——因此 `project_work_next` 把每个非终态条目列给每个调用方，他人持有的活跃租约虽有标注却仍在队列里。指派与交接两个域已发布、第二个 AGENT actor 即将注册，这个队列会把别人进行中的领取当作第二个 agent 自己的工作呈现。此次变更不得新增权威：readiness 保持重算，账本处于 schema 7、format 7、180 事件时间线，为显示过滤而动 schema 或格式都是放错位置的重量。

## 决策

- **视图请求获得查看者身份，其余不变**：`WorkTodoRequest` 上的 `viewerIdentity`，经解析后的 spec 携带、像 `executorKinds` 一样在视图上回显。给出查看者时，另一身份持有活跃领取的条目从视图中消失；无人领取的条目与查看者自己的条目保留。不给时，视图是全队列——与人用的 `/project todo --agent` 命令读到的是同一个视图。
- **过滤活在读取里，不在 readiness 里**：不加新的阻塞器种类，不改 `computeWorkReadiness`。被隐藏条目的租约阻塞器从来不是第二个 agent 该读的事实；未过滤视图照旧呈现持有者。
- **`project_work_next` 在自己的边界解析查看者**：点名了 agent 的会话按 `agent:<id>` 过滤（与领取和评估记录的身份一致）；无会话的执行没有可过滤的身份，列出全队列——这是在消费方显式解析，而不是视图内部的隐藏默认。空查看者身份响亮失败（`empty-viewer-identity`）——那是调用方错误，不是对未过滤视图的请求。
- **证据运行把条目传递终结在完成它的 actor 上**：第二个 agent `agent:second` 注册（事件 169），lane 在收尾条目上担 `PRIMARY`（`executor` 角色）（`wa:mini-dsh:170`），第二个 agent 领取（租约 171）——过滤视图按设计分裂：lane 的视图隐藏该条目，第二个 agent 的视图显示其为己所持，未过滤视图带标注显示——随后记录传递 `ho:mini-dsh:172`（`DELEGATE` 给 lane）并释放。lane 的运行随后领取、验证并把条目完成到 `DONE`。

## 验证

- `project-ledger`、`project-ledger-sqlite`、`mini-profile` 三包 345 测试，逐文件 100% 覆盖率：resolve 的拒绝、一个测试在给定查看者下覆盖自持/他持/无人持并钉住回显、一个工具层双 agent 测试——另一 agent 的 `project_work_next` 应答空队列而持有者仍看到自己的租约；无会话回退由既有的无 agent 列表测试覆盖，未改动。
- 门槛：oxlint 0/0，duplication 保持既有的两条 clone 基线，cordis catalog 干净。
- Lane：证据运行的快照（隐藏/显示/标注）经已发布的接缝取自持久账本；lane 运行存储 verifier 退出码 0，`PA-CLAIM-VISIBILITY-001` 到 `DONE`，doctor 0 issues、重放审计 0 drift；幂等重跑以零工具调用通过；4K 切片保持绿色（最大 2,444/4,096）。

## 考虑过的替代

- **带查看者参数的 readiness 阻塞器**——拒绝：为显示过滤而把查看者参数穿进可领取性概念，且视图是只读、无权威。
- **`project_work_next` 无 agent 会话时响亮失败**——拒绝：兄弟的 claim 与 update 工具需要身份是因为它们要写；无查看者的列表就是命令面已暴露的 owner 式队列，回退因此显式且有文档。
- **标注他持条目而非隐藏**——拒绝：提案的措辞是可见性而非标注；未过滤视图继续为人类提供标注。
- **把条目从 lane 传给第二个 agent**——拒绝：注册 actor 无法运行 verifier 或报告；第二个 agent 先领取以证明可见性分裂，再把工作委托给完成它的 lane，记录的传递因此终结在工作终结的地方。

## 后果

- v1.6d 阶段 A 以全部三项 `DONE` 收拢：工作指派、交接、按 actor 的领取可见性，时间线折叠 formats 1–7 的 180 个事件，两个注册 AGENT actor 之间有一次已记录的传递。
- 阶段 B（并行协作：范围预留与协作冲突）继承双 agent 阵容；两个 agent 现在读同一个队列而互不见对方的活跃领取。
- 无会话的 `project_work_next` 继续列出全部；未来需要在无会话时按 actor 过滤的消费者显式传 `viewerIdentity`。
